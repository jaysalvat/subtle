# CLAUDE.md — Subtle

Instructions for Claude (and any AI assistant) working in this repository. Read this first.

## The project

**Subtle Studio** is the name shown and communicated (UI, manifest, README, site); the repo, `subtle.jaysalvat.com`, the `.subtle` file format and the storage keys (`subtle.*`) stay `subtle`: never rename those (users' projects live under them).

Local web app to edit, retime, clean (hearing-impaired tags) and translate `.srt` / `.vtt` subtitles while watching the video. Everything runs in the browser, nothing is uploaded.

## Commands

- `npm run dev` — dev server on http://localhost:3000 (Chrome).
- `npm test` — Vitest, core library tests
- `npx tsc -p tsconfig.json` — type-check
- `npm run build` — type-check + production build (forces `NODE_ENV=production`: this shell has `development` set, which made Vite build React's dev version and drop production-only code)
- `npm run lint` — Oxlint (`.oxlintrc.json`; ESLint can't read TypeScript 7 yet); `npm run format` — Prettier (`.prettierrc.json`); `npm run check` — types, lint, format and tests together, as CI would
- GitHub Pages: `.github/workflows/pages.yml` builds with `BASE_PATH=/app/` (served at subtle.jaysalvat.com/app/, relayed by the site; repository variable `BASE_PATH` to change it). Paths go through the base: `import.meta.env.BASE_URL` in code, relative paths in the manifest, `BASE` in `src/sw.js`. Never a root path like `/sw.js`.
- `npm run release -- patch | minor | major` (Jay runs it, never Claude): from an up-to-date main, the notes written under `## Unreleased` in `CHANGELOG.md` become the version's; bumps, checks, builds, commits, tags, then asks before pushing main and the tag (never `--tags`). The tag starts `.github/workflows/release.yml` (GitHub Release with those notes, `scripts/changelog.mjs`). New user-visible work: add a line under `## Unreleased`, in its section (`### New tools`, `### Better tools`, `### Also`, as in 2.1.0), no blank line between items; say when a feature uses AI; make people want it without promising more than it does.
- `npx vite preview --port 4173` (launch config `preview`) — serve `dist/` to try the installed app: the service worker only runs in a production build

## Architecture (keep it this way)

- `src/lib/` — pure TypeScript, no React, no DOM except `TextDecoder`/`Blob`. Every tool (shift, sync, min duration, HI cleanup…) is a pure function `(cues, options) => cues`. **Any change here comes with a test in `lib.test.ts`.**
- `src/store/store.ts` — Zustand: document, selection, undo/redo, settings, autosave. Every user-visible change goes through `commit(cues, label)` so it can be undone. Live drags use `replaceLive` + `endGesture`. A tool's live preview uses `previewLive(base, cues)`: the project keeps saving `base` (`previewBase`) until `endGesture` (applied) or `replaceLive(base)` (cancelled); switching to another tool drops an unapplied preview.
- Store selectors never build a new array or object (`useApp((s) => s.doc?.cues ?? [])` makes a new `[]` each time: React loops, black screen). Use a module constant (`?? NO_CUES`) or select the raw value.
- `src/store/playback.ts` — current time, updated every frame. Components subscribe with selectors; never put per-frame state in the main store.
- `src/actions.ts` — commands shared by buttons, shortcuts and the timeline.
- `src/components/` — UI only. React hooks always go above any early `return` (e.g. `Timeline` returns early with neither subtitles nor video, `CueList` without subtitles; with a video alone the first insert creates an empty SRT doc in `commit`): a hook after it crashes the app when a project is restored.
- `src/features.ts` — features built but switched off for the release (translation is off for V1). Check it before assuming a feature is visible.
- `src/components/Icons.tsx` — every icon, from Iconoir (`iconoir-react`) behind our own names. Add new icons there, not inline SVG. Small bubbles (a count, the AI mark): `Pill` (`src/components/Pill.tsx`, `ai` for the AI mark, in `--ai`, the site's AI purple; styles `.pill` in `base.css`); **every feature that uses AI shows `AiPill`** (after its name, or `corner` on an icon button): it sells the product; menu items take `pill` (Tools marks every AI tool with `t.common.ai`). Dropdowns: `src/components/Menu.tsx` (a click outside only closes them: `swallowNextClick`; `columns={2}`: a wide menu, sections side by side (`menuColumns` in `src/lib/menu.ts`), ←/→ between columns, kept inside the window; used by Tools).
- Sounds, only two (more clashed with the message that follows): `playSound('done' | 'toast')` (`src/store/sounds.ts`, files in `src/sounds/`): `done` when a long job's progress ends with something to do (not stopped or failed: subtitles from the audio, translation, Review / Shorten with AI), `toast` with every `notify` (quiet within 1.5 s of `done`). Off with Settings › General › App › Play sounds (`settings.sounds`). A new long job plays `done` too; no other sound.
- Long jobs (subtitles from the audio, translation, Shorten with AI, model loading): always `ProgressBand` (`src/components/Progress.tsx`: title, spinner, Stop, bar, count or %, time left from `timeLeft` / `formatLeft` in `src/lib/time.ts`). Background work shown inline (dialogue and images in the timeline head, OCR): `ProgressBadge` (spinner, text, %, time left), same file, with `Spinner`. Never a progress bar or spinner of your own.
- Lists to pick from (languages, AI providers and models, local server): `ComboBox` (`src/components/ComboBox.tsx`: type to filter, keyboard, optional typed value, list in a portal, `renderOption` for custom rows), not a native select (except a handful of fixed choices first in a window, e.g. the app language in Settings: a ComboBox there takes the focus and selects its text). **Choosing a subtitle**: always `SubtitlePicker` (a ComboBox: number · time · text, the time a button that takes the video there; `src/components/SubtitlePicker.tsx`) or, always open, Sync by ear's `LinePicker` — both draw `SubtitleRow`.
- Choices among a few options with a line of explanation each (speech to text model, translation engine, subtitles from the film or a zip): always the card radios — `.engine-list` of `<label className="engine">` (radio, `<strong>` name, `.note` line; the chosen one framed in the soft accent; `disabled` greyed) — not a plain radio list.
- Number fields: `NumberInput` (`src/components/NumberInput.tsx`: our own ▲ ▼, hold to repeat), never a bare `type="number"`.
- Subtitle numbers in a list (issues, previews, Shorten with AI): `CueNumber` (`src/components/CueNumber.tsx`: "#12" everywhere, a button that goes there whenever it can, right-aligned, muted, accent on hover when `onGo` makes it a button).
- Warnings and good news inside a window or panel: always `Alert` (`src/components/Alert.tsx`: framed, orange `warning` or green `success`, `<strong>` for a number, `actions` for buttons), the first thing in the body, right under the title (`Dialog`'s `alert` prop; first in a side panel's body), never a note in orange or a box of your own.
- Messages: always `notify(text, { undo?, tone? })` (store) — shown with Sonner (`<Toaster>` in `App.tsx`). `undo: true` adds an Undo button (don't write "⌘Z to undo" in the text); `tone: 'success' | 'warning'`; `stay: true` keeps it until closed (when something is left to do, e.g. "25 couldn't be fixed"). Confirmations: `await ask({ title, text, ok, danger? })` (`src/components/Confirm.tsx`), never the browser's `confirm()`.
- `src/i18n/` — every user-facing string: `en.ts` gives the shape, `fr.ts` and `es.ts` the same keys in French and Spanish (typed `Translation`: a missing phrase shows in English, `fillFrom` in `src/lib/partial.ts`; a misnamed key is refused; `npm test` lists what's missing), `index.ts` picks the language at start (Settings › General › App (first) › Language, else the browser's; a change applies after a reload) and downloads only that one (English always there; the others are their own chunk, kept out of the offline precache) — import `t` from `src/i18n`. A new language: `xx.ts` + one line in `UI_LANGUAGE_INFO`. New text: add it to `en.ts` (other languages can follow later; French and Spanish are kept complete) (short, see the copy rules: one-line hints, no explaining what the screen shows). Language names come from the browser in the UI's language (`languageName`), decimals from `decimal()` (`src/lib/locale.ts`). No hard-coded copy in components.
- `src/styles.css` imports `src/styles/*.css` in order (the cascade depends on it): `tokens.css` (design tokens, see `DESIGN.md`), `base`, `topbar`, `player`, `panels`, `controls`, `menus`, `list`, `timeline`, `dialogs`, `toast`, `pages`. Use the variables, don't add raw colours; new styles go in the file of their area. A bar short of room never wraps: tag its info `priority-low` / `priority-medium` / `priority-high` and hide them in that order with container queries (`base.css` comment, transport bar in `player.css`).

## Checking in the browser

- `.claude/launch.json`: `app` attaches to the dev server already running on port 3000 (use it first); `dev` starts one if none is running.
- Load a subtitle without the file picker:
  ```js
  const { useApp } = await import('/src/store/store.ts');
  const text = await fetch('/samples/sample.en.srt').then((r) => r.text());
  await useApp.getState().loadSubtitleFile(new File([text], 'sample.en.srt'));
  ```
- Read state the same way (`useApp.getState().selection`, `.doc.cues`) rather than with screenshots.
- Hot updates everywhere (components, lib, i18n, CSS) so an edit doesn't lose what's on screen (AI results that cost tokens); only `src/store/` and `actions.ts` reload the page (`reloadOnStateChange` in `vite.config.ts`): a hot-updated store splits the app in two (shortcuts acting on another selection than the one shown). A lib module a store imports can still do that: if the app acts oddly after an edit, reload. `STRICT_HMR=1 npm run dev`: the old strict mode. After a reload the video has to be dropped again.
- Import the app's own module URL, which carries `?t=…` after hot reloads, or you get a second store: `const url = (p) => performance.getEntriesByType('resource').map(e => e.name).find(n => n.includes(p)) ?? '/src/' + p; const { useApp } = await import(url('store/store.ts'));`
- Test video without a real film: `const { makeTestVideo } = await import('/src/dev/makeTestVideo.ts'); useApp.getState().loadVideoFile(await makeTestVideo(60));` (H.264, numbered frames, no audio; `makeTestVideo(60, 10, 'mkv')` for an MKV). A short film with speech, if present locally: `/samples/speech.mp4` (not committed). The POC pages (audio, speech to text, sounds, voices, MKV) were removed once their work was in the app: see git history.

## Product rules

- Automatic tools never change the **start** of a subtitle (only Shift / Two-point sync do, and Align on the dialogue, behind a preview to accept).
- No overlaps: respect `settings.minGapMs`.
- Tags (`<i>`, `{\an8}`…) and VTT settings are preserved on import/export (SRT / VTT; the other formats keep italics and top / bottom only).
- UI in English, sentence case, buttons say what they do. Tool names start with a verb ("Shift times", "Convert frame rate") and the window title repeats the menu name. Menu items and buttons never end with "…" (only texts of work in progress do: "Translating…").
- Videos: MP4 / M4V, MOV, MKV, WebM, all through one demuxer, Mediabunny (`src/media/`, types in `src/lib/files.ts`). What plays is up to Chrome's decoders (no DTS sound).
